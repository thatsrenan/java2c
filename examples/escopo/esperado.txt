# Resultado esperado do PARSER COMPLETO (modo "parser" de tests/check.sh) para
# cada caso de examples/escopo.
#
#   NOME  ok                          programa deve ser ACEITO (exit code 0)
#   NOME  erro : ERRO SEMANTICO       programa deve ser REJEITADO por uma regra
#                                     de escopo, com a linha de erro comecando
#                                     por "ERRO SEMANTICO"
#
# CONVENCAO: erros de escopo/semantica devem ser impressos como
#     ERRO SEMANTICO na linha N: <descricao>
# Exigir esse trecho evita que um caso passe "por acidente": hoje E05 e E07 sao
# rejeitados, mas por ERRO DE SINTAXE (o parser ainda nao aceita funcoes), e
# isso NAO conta como a rejeicao de escopo esperada.
#
# As expectativas seguem as regras de escopo do Java:
#  - uma variavel local so existe dentro do bloco onde foi declarada;
#  - redeclarar um nome no mesmo escopo e erro (inclusive parametro x local);
#  - uma variavel local NAO pode ocultar outra variavel local visivel
#    (bloco externo, ou variavel de for), mas PODE ocultar uma variavel
#    global (static);
#  - a variavel do init de um for so existe dentro do for.
#
# Casos comentados no fim dependem da especificacao do projeto: sem uma linha
# aqui eles aparecem como [AVISO] e nao entram na contagem.
